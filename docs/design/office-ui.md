# Office UI

The full reference (`CLAUDE.md` keeps only the essentials).

**Rendering**: Game state in imperative `OfficeState` class (not React state). Pixel-perfect: zoom = integer device-pixels-per-sprite-pixel (1x–10x). No `ctx.scale(dpr)`. Default zoom = `Math.round(2 * devicePixelRatio)`. Z-sort all entities by Y. Pan via middle-mouse drag (`panRef`). **Camera follow**: `cameraFollowId` (separate from `selectedAgentId`) smoothly centers camera on the followed agent; set on agent click, cleared on deselection or manual pan. The camera centres on a clicked character and follows it (`cameraFollowId`), and centres the same way on a clicked piece of interactive furniture (`cameraPieceUid`, the middle of its sprite, `pieces.center`); a followed character outranks a piece, and a manual pan or a tap anywhere else lets go.

**UI styling**: Pixel art aesthetic — sharp corners (`borderRadius: 0`), solid backgrounds (`#1e1e2e`), `2px solid` borders, hard offset shadows (`2px 2px 0px #0a0a14`, no blur). CSS variables in `index.css` `:root` (`--pixel-bg`, `--pixel-border`, `--pixel-accent`, ...). Pixel font: FS Pixel Sans (`webview-ui/public/fonts/`, WOFF2), loaded via `@font-face` (`font-display: block`: text waits for it rather than flashing in the system font) and preloaded by `index.html`, applied globally. The standalone server lets browsers keep the font (30 days) and Vite's hashed bundles (for good): `httpServer.ts` `staticCacheControl`; everything else is revalidated on every load.

**Pixel icons are 8×8.** Every UI icon is an 8×8 grid in `components/ui/pixelIcons.ts` (`#` = lit pixel, drawn in the text colour), rendered at `PIXEL_ICON_SCALE` whole screen pixels per icon pixel (2 → 16 px). Never scale an icon fractionally: blurred edges break the pixel look. `PixelIcon` also guards against the display doing it: at a browser zoom or scaled display (1.25x, 1.5x) it draws each icon pixel as the whole number of DEVICE pixels at or below `scale` (`components/ui/pixelSnap.ts`, ratio from `hooks/useDevicePixelRatio.ts`), else some rows come out a device pixel thicker than others. Position needs no help — the browser paints each box from a whole device pixel, so nudging one by its fractional offset shifts it a full pixel. To shrink one, step the whole-number scale down (`<PixelIcon name="close" scale={1} />`, 8 px — the roster cards' ×) or draw the shape smaller inside the 8×8 (`zoomIn`/`zoomOut`). Buttons take `icon="<name>"` and draw it left of the label, vertically centred.

**Numbers use the pixel number font.** A 3×5 font drawn as pixel art (`components/ui/pixelFont.ts` glyphs + `splitLabel`, `PixelText.tsx`): only number words ("73%", "-40", "3d 11h", "3x", "v1.5", "1 / 21", an upper-cased hex "#1E1E2E", a month "OCT 13", a moment ago "NOW" — `timeAgo` writes dates with `MONTHS`, never the locale's) become glyphs, everything else stays in FS Pixel Sans. Use `<PixelText text=… />` (`smaller` = one device pixel less per glyph pixel, a crisp in-between on 2x/3x screens — the sidebar's times) wherever the UI prints a number (history times, slider values, zoom level, version, usage bars); a text field shows it through `PixelInputText` (the field's own text is transparent until focused). A new character needs its glyph and the `NUMBER_WORD` pattern.

Custom ESLint rules (`eslint-rules/pixel-agents-rules.mjs`) enforce: `no-inline-colors` (hex/rgb/rgba/hsl/hsla literals only in `constants.ts`), `pixel-shadow` (must use `var(--pixel-shadow)` or `2px 2px 0px`), `pixel-font` (must reference FS Pixel Sans). All `error`-level — they block PRs.

**Characters**: FSM states — active (pathfind to seat, typing/reading animation by tool type), idle (wander randomly with BFS, return to seat after `wanderLimit` moves). 4-directional sprites, left = flipped right. Tool animations: typing (Write/Edit/Bash/Task) vs reading (Read/Grep/Glob/WebFetch). Sitting offset: characters shift down 6 px in TYPE state. A TYPE character that isn't active (resting in its chair after wandering, or held by `seatTimer` — a usual rest is `restInChair`) shows the **seated** frame instead of typing; helpers (sub-agents) never do — they keep typing through the gaps between tools and stand once idle. Z-sort uses `ch.y + TILE_SIZE/2 + 0.5` so characters render in front of same-row furniture but behind lower-row furniture. **Chair z-sorting**: non-back chairs use `zY = (row+1)*TILE_SIZE` (capped to first row); back-facing chairs use `zY = (row+1)*TILE_SIZE + 1` so the chair back renders in front of the character. Chair tiles are blocked for all characters except their own assigned seat (per-character pathfinding via `withOwnSeatUnblocked`).

**Palette assignment** — a launch's look is ONE pure choice, `core/src/paletteUtils.ts` `chooseLook` (server: `paletteAssigner.assignPaletteIfNeeded(agent, store, { picked, directory })` on both surfaces; the webview's fallback for an agent the server gave no look calls it too). First match wins: a roster pick (`launchAgent.palette`, worn even if taken), else the launch Directory's **default characters** (`Directory.characters`, highest priority first, set in the Directory modal; `characterOrder` `priority` = the first one no agent wears, `random` = a random unworn one; either way all worn → fall through, a default in the office is never repeated — `core/src/directoryCharacters.ts` `pickDirectoryCharacter`), else `pickRandomPalette()`: a random character among those with the fewest copies in the office (one no agent wears while any is free, then a random repeat, never a third copy of one until every character has a second), preferring ones no Directory claims as a default (`directoryDefaults()`, so a Directory's characters stay free for its own launches). **A look is `{ palette, repeat }`**: `repeat` says which copy of its character an agent is (`repeatFor`: the lowest no other copy holds, 0 when no one wears it; teammates and sub-agents copy their lead's). The look names no colours: the nth repeat is drawn with every piece of clothing colorized to the nth colour of `REPEAT_CLOTHES_HUES` (red, blue, green, yellow, purple, cyan, pink, then more, cycling; `core/src/characters/repeatClothes.ts` `withRepeatClothes`: underwear, pants, top, outfit, jacket, shoes, hat; skin, hair, eyes and accessories stay), rendered from the profile on demand (`officeSprites` hands `setCharacterTemplates` the sheets and their repeat source together); an external `char_N.png` has no clothes to tell apart, so its repeat is hue-turned whole (`repeatHueTurn`, `adjustSprite`). Palettes = the character profiles, then any external `char_N.png` (server: `getPaletteCount()`). The launch drawer shows a Directory's defaults as 1x mug shots side by side: up to 4 all show; from 5, the first 3 (random order: 3 random ones) plus a dark blank-character silhouette with "..." (`DirectoryCharacterStrip`, `directoryStrip.ts`); pressing a mug shot launches as that character (`launchAgent.palette`), pressing the "..." shows every default (6 to a line, until the drawer closes); a drawer opened by a roster pick (`LaunchDrawer` `pick`, from `useRosterLaunch`) shows only the Directory names and launches as the pick, the rest of the row launches in the Directory's order, and a row's buttons (`drawerRowButtons.ts`: the pencil on user rows) are drawn as a small stack outside the drawer, hanging off its right border level with the hovered row (re-measured by a `ResizeObserver`); on touch a long press on the row reveals its stack instead (it never launches), a press outside hides it. Character stores `palette` (profile index) + `repeat`; older saves' looks in degrees (`clothesHue`, and `hueShift` up to v1.5) are read as "a repeat" (non-zero = 1). **A palette is an index, so the list keeps them on their character**: every profile has a permanent `id` (`char-<index>` for a list saved before ids, a fresh one for every character the cast adds, copies and loaded configs included), and a save (or a `characters.json` rewrite) that inserts or deletes characters is matched old to new by id (`core` `characterRemap`). `server/src/characterRemap.ts` renumbers this process's agents and their saved seats (an agent whose character was deleted gets a new look; a follower copies its lead's) and sends them as `characterProfilesLoaded.agentLooks`, applied with the list (`officeState.setAgentLook`); the process that saved also renumbers the machine-wide references (Directory defaults, the roster's recency, past conversations' looks) and re-sends Directories and recency. Sprite cache keyed by `"palette:repeat:blink"` (a palette that can't blink shares its open-eyed set under the blink key). **The server owns each agent's look** (picked at creation; a teammate copies its lead's): `saveAgentSeats` only fills a look an agent doesn't have yet, and a reconnect's `existingAgents` re-applies look and seat to characters the office already shows (`syncAgent`) — a stale browser saving back its old ones used to reshuffle the office for every viewer.

**Visits**: the character's errands (`Character.errands`, `engine/visitsController.ts`: the server Visit at the bottom, a local errand above it; `os.visits.start(id, stops, then)` — stops walked in order, each faced and stood at for its `lingerSec` (default `VISIT_LINGER_MS`), then `wander` / `stay` / `seat`; `end`; `stopOf`) takes the character out of the usual FSM: its agent's work doesn't move it until the visit ends (the server's `cleared` on the next turn, then an active agent heads for its seat). A repeat of the visit under way (snapshot) keeps its progress; a stop this office can't walk to drops it; a layout rebuild doesn't snap a visitor to its seat; the user's seat click / walk command ends it. **Message show** (`agentMessageShow` → `visits.showMessage(fromId, toIds, gist, { walk })`, `visits.gistOf`): a MessageShow errand pushed over the server Visit (dropping Buildout work) whose stops stand `beside` each recipient (aimed by the office — `spotBeside` around where that character stands or is walking to, re-aimed as it moves, the sender's own tile as the start) and `say` the gist while arrived (`MESSAGE_SHOW_LINGER_MS` each), then `seat`; recipients absent, leaving or unreachable are skipped; a second show queues after the first; a server `agentVisit` replaces it (server wins), a server `cleared` only drops the server Visit under it (the show carries on, then `seat`); a Visit under a finished errand is walked again. Reduced motion or no one to walk to: the gist shows in place (`ch.saying`).

**Buildout** (`layoutLoaded.buildout { agentId, origin }` — only on an agent edit's broadcast that names a tile, never undo / saves / the connect snapshot → `OfficeState.startBuildout(layout, buildout, shift)` (playing in `os.buildout`, `engine/buildoutPlayer.ts`); reduced motion or a first layout → plain `rebuildFromLayout(layout, shift)`; `layoutLoaded.shift` moves characters and pets with a resize either way): the office's state is the new layout at once, only drawing follows the plan (`engine/buildout.ts`, pure: per-tile floor/wall/carpet changes and per-uid furniture changes, diffed against the layout the office held, lined up by `shift`; a changed item dissolves as its new self appears; nearest the origin first, `BUILDOUT_STEP_SEC` apart, squeezed into `BUILDOUT_MAX_SEC`; removals — walls, floor erased to void, items gone or changed — dissolve via `renderMatrixSprite`; carpets swap without rain; Areas and pets aren't animated). The renderer reads `shownLayout()` / `shownTileMap()` / `buildout.render()`. The builder gets a BuildoutWork errand (over its server Visit, never over a Message show; a `work` stop beside the origin: typing standing up for the build's length + `BUILDOUT_WORK_TAIL_SEC` once there, then its seat); the build never waits for the walk. Any later layout ends a buildout under way (its result shows at once); another edit builds from it.

**Spawn/despawn effect**: Matrix-style digital rain animation (0.3 s). 16 vertical columns sweep top-to-bottom with staggered timing. Spawn: green rain reveals character pixels. Despawn: character pixels consumed by green rain trails. `matrixEffect` field on Character (`'spawn'`/`'despawn'`/`null`). Normal FSM is paused during effect. Restored agents (`existingAgents`) use `skipSpawnEffect: true` to appear instantly.

**Sub-agents**: Negative IDs (from -1 down). Created on `agentToolStart` with "Subtask:" prefix, or lazily by `subagentToolStart` when missing (watched background spawns, post-reload recreation). Same palette + repeat as parent. Click focuses parent terminal. Not persisted. Spawn at the closest free walkable tile to the parent's seat (the parent itself when it has none, `anchorTile`) — around it, never in a seat. They never wander and never trail a wandering lead: `updateHelper` keeps them within `HELPER_FOLLOW_RADIUS_TILES` of that home tile, walking back when it moves (a reseated lead), facing it, sitting in place (no chair under them) while working and standing while idle. Idle (stop typing) when every tracked sub-tool row is done; overlay shows the latest non-done sub-tool status, falling back to the Subtask label.

**Speech bubbles**: Permission ("..." amber dots) stays until clicked/cleared. Waiting (green checkmark) auto-fades 2 s. A Message's gist is a text bubble (`pixel-panel`, wraps at `MESSAGE_BUBBLE_MAX_WIDTH_PX`, `data-testid="agent-gist"`) that outranks the sprite ones while shown. Sprites in `spriteData.ts`.

**Sound notifications**: Ascending two-note chime (E5 → E6) via Web Audio API plays when waiting bubble appears (`agentStatus: 'waiting'`). `notificationSound.ts` manages AudioContext lifecycle; `unlockAudio()` on canvas mousedown resumes the context (webviews start suspended). Toggled via Settings modal. Persisted per-namespace in `~/.pixel-agents/config.json`.

**Office radio** (`music/`): procedural 8-bit background music in the office's bottom-right corner (phone: centred, tucked below the office's foot behind a "Swipe up for music" hint, dragged up and down as a sheet, `playerSheet.ts`). Play/pause, skip, volume, a mood (Auto or one of `MOOD_KEYS`) and a **song code** (`TOWN-5-8F3A21C0`: mood, root, seed) to share a tune or play one. A tune is fully determined by its seed, mood and root (`makeSong`), so **the order of every random draw in the composer is part of the song-code format** — `musicComposer.test.ts` pins tunes and codes; a change that moves a draw changes every shared tune. Never plays on its own (browsers start audio only from a click). Hidden or shown from Settings → Music Player (per browser). On desktop it never moves and never covers the bottom-left toolbar: as the office narrows (a narrow VS Code panel, a wide terminal drawer) it gives up the visualizer, then the tune's name and mood, down to its buttons (`playerFit.ts`; lifted above the toolbar's row it covered the layout editor's tools); the terminal drawer can't be dragged past the width that leaves the office room for both (`OFFICE_MIN_WIDTH_PX`, `hooks/drawerWidth.ts`), and in a host we can't stop from shrinking further the toolbar draws over the player. The version label rides above the player through `radioLift.ts` (`setRadioLift` / `aboveRadio`).

**Mobile shell** (standalone only): below `MOBILE_MEDIA_QUERY` the browser renders `mobile/MobileShell` instead of the desktop layout — office and terminal as two full-screen pages in a 200%-wide sliding track (both always laid out, never `display:none`, so the canvas and xterm keep dimensions); the track's transform makes it the containing block of `position: fixed`, so modals and other viewport overlays mount at App's top level, never inside the office region), the agent cards in a bottom scroller (the same `AgentCardList` as the desktop column: same cards, same server-owned order — `cardOrderLoaded`/`saveCardOrder` — so a reorder on one device moves the cards on every open office), and `MobileKeyBar` above the software keyboard. "Keyboard open" and "clamp the shell" are separate answers (`mobile/keyboardViewport.ts`, sampled by `useKeyboardViewport`) because the two resize policies differ: iOS shrinks only the visual viewport (open, and the shell is clamped to it so the PTY resizes instead of hiding its input line), Android `interactive-widget=resizes-content` shrinks both (open, nothing to clamp). Open = an editable focused AND the visual viewport `KEYBOARD_MIN_HEIGHT_PX` below the tallest height seen at the current width (per-orientation baseline). `useIsMobile` is gated on `isBrowserRuntime`: a narrow VS Code panel must never get it (it broke every VS Code e2e shard once). Navigation rules live in `useMobileShell`: the >_ / Office toggle and the edge swipe share one handler; a card tap in the office is two-step (focus the character, then open its terminal), in the terminal it switches panes; + slides over only for launches made from it (a reload re-announcing sessions stays on the office): App reacts to `useTerminalDrawer`'s `lastLaunched`, set only for the first terminal to open after `expectLaunch`, and only within `LAUNCH_ANSWER_TIMEOUT_MS` (`hooks/launchLatch.ts`): a spawn that fails opens no terminal and no message says so, and an armed latch would otherwise claim the next terminal any device opens. an arrow right of the + card (a narrow `ROSTER_ARROW_WIDTH_PX` tab beside the square +, both as tall as `AGENT_CARD_HEIGHT_PX`; accessible name "Roster", `aria-expanded`; on both pages; it points up while shut and turns down while open, and a tap toggles) opens the roster (`CharacterPicker`, a full-width strip that slides up from behind the card bar; the arrow stays to close it), not the Characters view: a tap picks the character and opens the + card's Directory drawer, whose launch carries it as `launchAgent.palette` (worn even if taken, then in the next clothes colour); a long press (`useLongPress`, as a Directory row's reveals its buttons) and the leading `+ New` slot open the Characters view on it. Desktop (both surfaces) runs the same flow (`useRosterLaunch`, hover and pin by `useHoverPin`) from the toolbar's + card, drawn like the phone's (a square `+` — accessible name "New agent" — with the roster arrow beside it, then Layout, and Settings only where no conversation sidebar holds it): the carousel shows above the toolbar without animation, and a hovered card's pencil edits; VS Code's `launchNewTerminal` honours `palette` too (`applyPickedPalette`). The terminal-pane model (active vs shown pane, socket status, `statusFor`) is `useTerminalDrawer`, shared with the desktop drawer. Touch rules: every gesture tracks ONE finger by identifier (`findTouch`) and uses one tap slop (`withinTapSlop`); gesture decisions are pure reducers with thin DOM adapters (`edgeSwipe.ts`/`useEdgeSwipe.ts`, `terminal/touchGesture.ts`/`touchInput.ts`, the radio's `music/playerSheet.ts`/`usePlayerSheet`; the key bar's trackpad sends left/right twice as fast as up/down, accelerating so a drag from the press point to a screen edge sweeps the terminal's full line (`TerminalInputHandle.cols`), and holds one axis per slide, re-deciding only after the finger rests, `touch/trackpad.ts`), because WebKit keeps addressing a gesture's events to its touchstart node — when terminal rows repaint, that node detaches and events stop bubbling, so each adapter binds "rescue" listeners on the touch target. **Terminal copy is verbatim by default**, except that a token Claude Code broke across rows (a URL, a path: `hardWrap.ts`) always comes back whole — that break's signature is one an intended newline doesn't have, and links (tap or click) follow it the same way (Cmd/Ctrl+C, the browser's Copy, the pill's Copy; paste is a long press on the input area — the cursor's row out to the prompt box's rules (`terminal/inputArea.ts`) — not a key; the same pill carries "Attach file"): re-flowing (`terminalCopyText`'s `'text'` mode) is a heuristic that joins a long row with a two-space-indented next line, which is also what YAML under a long key or a method body under a long signature look like, so re-flowing is opt-in only — Alt+C (Option+C) on desktop, "Copy as text" on the pill. Every write goes through `terminal/clipboard.ts`. **Files go to a terminal the way a native one takes a dropped file**: dropped on the pane (desktop) or picked through the input area pill's "Attach file" (phone), each is POSTed to `/api/terminal/:agentId/files` (the terminal socket's gate; streamed to disk, `TERMINAL_UPLOAD_MAX_BYTES`), saved in the host's upload directory — Settings → Save Sent Files To (`setUploadDirectory`, per namespace), else our own `~/.pixel-agents/uploads`, the one folder the server sweeps (files sent more than 7 days ago, then the oldest past 2 GB; a folder the user chose is never cleaned) — under a name that is safe on every OS and never overwrites (`photo-2.jpg`), and the saved path is pasted through xterm (one bracketed paste, which is how Claude Code tells a dropped image from typed text), quoted as that OS's terminals do (`terminalPathText`: backslashes on POSIX, double quotes on Windows). The server answers the path as text, so the browser never guesses the host's OS. **A file already on the host is not copied**: a page on a loopback hostname first asks `POST …/files/locate` with the file's name, size and modification time (all a browser knows of it; it never learns a path), and the server (`terminal/localFile.ts`, loopback `Host` only) looks for that very file — straight under the home directory, its Desktop, Downloads and Documents the upload directory and the Directories the user added, never deeper and with no search of the disk — checking candidates in a child process with a timeout (a stat of a protected macOS folder can block a background process forever). Found = its own path is pasted and nothing is uploaded; not found = the upload and a copy, as from another machine. PWA: `manifest.webmanifest` (icon paths relative — the file is served verbatim), conventional-path icons in `public/`, `?v=N` cache-busters on icon links.

**Seats**: Derived from chair furniture. `layoutToSeats()` creates a seat at every footprint tile of every chair. Multi-tile chairs produce multiple seats keyed `uid` / `uid:1` / `uid:2`. Facing direction priority: 1) chair `orientation` from catalog (front→DOWN, back→UP, left→LEFT, right→RIGHT), 2) adjacent desk direction, 3) forward (DOWN). Click character → select (white outline) → click available seat → reassign; clicking a workstation (a PC) instead seats it at the chair paired with it (`seatOfPiece`), the PC often hiding that chair — its own seat sends it back there, someone else's leaves the PC's own click.
